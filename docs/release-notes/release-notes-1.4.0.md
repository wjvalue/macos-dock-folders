# v1.4.0 — 落盘目录收进 Application Support，home 目录不再留东西

## 为什么

之前装完之后 home 目录里会多一个 `~/Dock Groups/` 文件夹，看着像「app 之外
还必须有这么个东西」。查证后确认：分组内容**没法内化进 .app** ——

- **bundle 是签名封存的**：往里写一个文件，`codesign --verify` 立刻报
  `sealed resource is missing or invalid`，Gatekeeper 拒绝。而分组内容每次增删
  App 都要变。
- **Dock 图标必须指向磁盘上的真实路径**：每个分组要带自己的图标和 Info.plist，
  所以 N 个分组 = N 个 .app。
- **分组文件夹是「唯一事实来源」**：里面是 Finder 真别名，拖放加入分组靠它。

所以这一版**把位置收敛掉**，而不是消除：

| | 之前 | 现在 |
|---|---|---|
| 分组数据 | `~/Dock Groups/` | `~/Library/Application Support/DockGroup/data/` |
| home 目录 | 多一个文件夹 | **干净** |

## 升级是自动的

第一次运行新版（`dg` 任意命令、或双击新版 DockGroup.app）会自动：

1. 把 `~/Dock Groups/` 整体搬到新位置；
2. 重建启动器（它们记录的文件夹路径变了）；
3. 把 Dock 上的分组图标**原地**换成新路径（位置不动，你手动排的顺序不受影响）；
4. 装过自动监听的，重装一次。

旧目录搬完就没了，不需要手动清理。**加 App 的方式**：管理窗口里点
「在 Finder 里打开」，或者直接把 App 拖进窗口。

## 升级路径上的三个坑（都已修）

升级到这一版时，**旧版的 `/Applications/DockGroup.app` 不会自动更新** —— 它是
安装时拷过去的独立副本，落盘路径编译期烧死。旧副本会去老位置找配置，找不到就
按「首次运行」建一个空的，看起来就像**配置丢了**。三处一起修：

1. **`dg gui` 现在会把 `/Applications` 那份自动换成新版**（判据是可执行文件字节，
   一样就不动，避免白刷 Dock 图标）。只认我们自己的 bundle id，绝不覆盖别人的。
2. **引擎不再拿安装根里的旧源码编译**：以前标记文件无条件优先，本机开发时改仓库
   源码、重编 `dg`，管理窗口却是旧源码编的。现在「本机存在的源码树」优先。
3. **迁移时结束旧版管理窗口进程**：不杀它就会一边往旧位置写、一边把空壳留在那儿。

另外把警告文案改对了：数据已经在新位置时**没有**可迁移的内容，旧目录多半是旧版
留下的空壳，确认后直接删即可。

## 顺带修掉

- **重签必然失败**（`resource fork, Finder information, or similar detritus not allowed）：
  自定义图标写下的 `FinderInfo` 会让下一次 codesign 失败，产物带坏签名。
  这个 bug 从引入自定义图标起就存在，只在「改了材质/风格后重跑」时才现形。
  现在签名前先清掉，产物签名有效。
- **`dg --version` 不再触发迁移**：纯查询命令不该有副作用。

## 兼容性

- 环境变量 `DOCKGROUP_HOME` 语义不变（仍指落盘目录本身），脚本和测试不受影响。
- 对照测试：67 项里 66 项通过，1 项（`preview` 对比图 MAE）是**既有**失败，
  与本次改动无关（在改动前的 HEAD 上复现同样的 9.6426）。
